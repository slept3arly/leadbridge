## Findings

- Root files reviewed: 16, including the local `.env` by name/status only; its values were not accessed.
- Tracked root files: all listed except `.env`, `next-env.d.ts`, and `tsconfig.tsbuildinfo`; `.env` and generated artifacts are ignored. `.env.example` remains tracked due to an explicit allowlist.
- PowerShell scripts are not referenced in repository documentation or code found by text search. This does not establish that they are unused: Windows Task Scheduler, shortcuts, operator habits, or external deployment automation may invoke them.
- `Start-LeadBridge.ps1` is operationally significant despite lacking in-repository references. Its fixed paths and database service name bind it to a particular Windows host.
- `backup-database.ps1` is operationally significant and includes backup retention/removal behavior. Its hard-coded roots and PostgreSQL install path also bind it to a particular host.
- There are no evidence-backed REMOVE or MOVE recommendations. No file should be removed or relocated solely because a repository text search did not find a caller.
- The current worktree already contains an untracked `docs/audits/PROJECT_DIRECTORY_INVENTORY.md` from the previous inventory request; this audit did not alter it.

## Final summary

1. **Root files reviewed:** 16.
2. **Keep:** `.env`, `.env.example`, `.gitignore`, `.prettierrc`, `AGENTS.md`, `README.md`, `eslint.config.mjs`, `next.config.ts`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `postcss.config.mjs`, `prisma.config.ts`, `tsconfig.json`.
3. **May be removed:** None supported by current evidence.
4. **May be moved:** None supported by current evidence.
5. **Generated files:** `next-env.d.ts` and `tsconfig.tsbuildinfo` are ignored and not tracked; `.env` is ignored and not tracked. The first two are generated/cache artifacts; `.env` is sensitive local configuration rather than generated.
6. **Unresolved questions:** Are either PowerShell scripts invoked by Task Scheduler, operator shortcuts, or external automation? Are their hard-coded paths/services still current? Should generated Prisma client output remain ignored and locally generated by `postinstall`? (Current `.gitignore` excludes `/src/generated/prisma`.)
7. **Recommended actions, in priority order:** (1) verify external/manual use and host assumptions for the backup script; (2) verify external/manual use and deployment assumptions for the startup script; (3) retain ignored generated files outside version control and allow the established generators/compiler to recreate them; (4) retain all other root configuration and manifests.
